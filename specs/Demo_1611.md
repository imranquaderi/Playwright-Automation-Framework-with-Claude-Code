# Demo_1611

## Application Overview

Happy-path test plan for logging into the QKart web application (`/login`) on the QA site `https://crio-qkart-frontend-qa.vercel.app`. Every scenario starts from a fresh browser state, is independent, and creates its own user first through `/register` with a unique username (see `uniqueUsername()` / `registerUser()` in `tests/helpers/auth.ts`), so no seeded accounts are needed. Inputs: `#username`, `#password`. Buttons, links and toasts use case-insensitive role/text regex locators. Valid password used in examples: `abcdef`. New users start with a wallet balance of `5000`.

## Test Scenarios

### 1. Login - Happy Path

**Seed:** `tests/seed.spec.ts`

#### 1.1. Log in with valid credentials

**File:** `tests/Demo_1611/login-valid.spec.ts`

**Steps:**
  1. Register a new user with a unique username and password 'abcdef'.
    - expect: Toast 'Registered Successfully' is shown
    - expect: Page redirects to /login and heading 'Login' is visible
  2. Fill #username with the new username and #password with 'abcdef'. Click 'Login to QKart'.
    - expect: Toast 'Logged in successfully' is shown
    - expect: Page redirects to / (products page)

#### 1.2. Logged-in header shows the user's details

**File:** `tests/Demo_1611/login-header.spec.ts`

**Steps:**
  1. Register a new user and log in with valid credentials.
    - expect: Header shows the user's avatar image (alt text = username) and the username text
    - expect: 'Logout' button is visible
    - expect: Header 'Login' and 'Register' buttons are no longer shown
    - expect: Product search box is visible on the landing page

#### 1.3. Session is stored in localStorage after login

**File:** `tests/Demo_1611/login-session.spec.ts`

**Steps:**
  1. Register a new user and log in with valid credentials.
    - expect: localStorage `username` equals the logged-in username
    - expect: localStorage `token` is present (non-empty)
    - expect: localStorage `balance` is '5000'

#### 1.4. Session persists after page reload

**File:** `tests/Demo_1611/login-reload.spec.ts`

**Steps:**
  1. Register a new user and log in with valid credentials.
  2. Reload the page.
    - expect: Username is still shown in the header
    - expect: 'Logout' button is still visible
    - expect: localStorage `username`, `token` and `balance` are unchanged

#### 1.5. Log in starting from the products page header

**File:** `tests/Demo_1611/login-from-header.spec.ts`

**Steps:**
  1. Register a new user, then go to / as a guest.
    - expect: Header shows 'Login' and 'Register' buttons
  2. Click the header 'Login' button.
    - expect: URL becomes /login
  3. Log in with the new user's credentials.
    - expect: Toast 'Logged in successfully' is shown
    - expect: Redirect to / with the username shown in the header

#### 1.6. Log out after a successful login

**File:** `tests/Demo_1611/login-logout.spec.ts`

**Steps:**
  1. Register a new user and log in with valid credentials.
  2. Click 'Logout'.
    - expect: Header 'Login' button is visible again
    - expect: localStorage `token` is cleared (null)
